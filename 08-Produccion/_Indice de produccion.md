# Preparación de demo y operación

El objetivo documentado inicialmente es **demo de hackathon**, no servicio comercial. Paulo evalúa si ampliar a cobertura funcional o piloto en [[Decisiones de Usuario para el desarrollo|DEC-19]]. El PDF §9 pide prototipo, código fuente, presentación, demostración en vivo y explicación de frontend, backend, base, APIs, IA si aplica y servicios externos.

| Entregable | Preparación | Estado |
| --- | --- | --- |
| Prototipo funcional | recorrido cliente→comercio→retiro, QR simulado y efectivo | Pendiente |
| Código fuente | repositorio/proyecto reproducible y migraciones de datos ficticios | Pendiente |
| Presentación | problema, usuarios, valor, funcionamiento, stack y proyección real | Pendiente |
| Demo en vivo | dispositivo, cuentas de roles, datos seed, conectividad y plan de contingencia | Pendiente |
| Arquitectura | React Native, Supabase/PostgreSQL, RLS, operaciones críticas y servicios usados | Diseño propuesto |

Antes de una demo real: confirmar propietario de cuentas, restaurar entorno, probar flujo y expiraciones, respaldo mínimo de datos demo, revisar costes/cuotas y secretos, ensayar desconexión. Producción comercial, pagos reales, políticas legales y despliegue continuo requieren decisiones nuevas; no se presuponen.
